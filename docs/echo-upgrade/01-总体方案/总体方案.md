# 声骸升级辅助（UpgradeEchoTask）总体方案

> 状态：方案定稿（v1.0）　｜　最后更新：2026-10-31
> 关联代码：`code/UpgradeEchoTask.py`（骨架）　｜　关联开发计划：`02-开发计划/开发计划.md`

---

## 1. 目标

用户事先在游戏内筛选好待升级的声骸并按等级升序排序后，程序自动逐件定位这些声骸，并把每件强化到运行期指定的目标等级 x（x 由用户运行时通过配置指定）。

**成功标准（DoD）：**

- 能稳定、批量地把多件声骸强化到指定等级 x，单件处理闭环完整；
- 材料不足、贝币不足等资源类异常能**优雅结束并通知**，而不是报错崩溃；
- 具备断点续跑能力：补充材料后再次启动即可从剩余声骸继续，无需状态文件；
- 关键坐标与阈值集中为常量，游戏改版时能快速重新标定。

## 2. 范围

**In scope：**

- 定位并读取声骸当前等级；
- 打开强化（培养）界面，投料至目标等级，执行强化；
- 目标等级的判定（预览等级闭环 + 档位模式降级）；
- 异常处理：材料/贝币不足、等级 OCR 失败、强化后未达预期、弹窗干扰、单件超时；
- 任务注册、配置项、统计与通知。

**Out of scope（明确不做）：**

- 副词条（双爆/有效词条）判定与弃置 —— 这是参考项目 `EnhanceEchoTask` 的能力，本功能删除；
- 同步调谐 —— 本功能**关闭**调谐，省调谐器并减少失败路径；
- 图像识别逐个声骸（网格点击、列表滚动） —— 采用"队列取首格"策略，见决策 1；
- 精确退料到任意等级（清空材料再逐个小料添加） —— 暂不做，仅"允许溢出"；
- 多账号、多语言（仅支持 zh_CN / zh_TW）。

## 3. 关键决策

### 决策 1：不识别列表，把列表当队列（取首格）

**理由**：用户预筛 + 按等级升序排序后，列表第一格永远是最低级的待升级件；升完一件它等级变高、自动排到队尾，第一格自然变成下一件。

- 好处：无需识别"这是哪件"、无需滚动与网格虚拟化处理、不受分辨率影响、天然支持断点续跑。
- 否决的备选：图像识别 + 网格点击（路线 B），成本高、游戏改版即失效，仅在"跳选特定声骸"时才值得做。
- **这是参考项目 `EnhanceEchoTask` 验证过的策略。**

### 决策 2：目标等级用"预览等级闭环"，经验表仅作降级

强化面板点「阶段放入」后界面显示投入材料后的结果等级，这是唯一可信真值。

| 层级 | 机制 | 精度 | 采用 |
|---|---|---|---|
| A 预览闭环 | OCR 预览等级 → 到 x 停 | 高 | **默认** |
| B 经验模型 | `echo_exp.json` 经验表算投放组合 | 中 | 可选增强 |
| C 档位模式 | 只支持 5/10/15/20/25，数阶段次数 | 高但粗 | A 失败时降级 |

溢出策略：材料粒度固定，可能无法精确停在 x；默认"允许溢出到最近可达等级并告警"。

### 决策 3：材料不足是"正常结束"，不是异常

材料耗尽时**正常 `return` + `notify`**，而非抛异常（抛异常会导致任务红屏失败）。筛选与排序仍保留，用户补材料后再点一次开始即可续跑，无需状态文件。

### 决策 4：坐标集中为类常量，归一化 0~1

所有识别区域用归一化坐标（跨 1280×720 ~ 2560×1440 通用），集中为 `UpgradeEchoTask` 的类常量，便于游戏改版后快速重标定。

## 4. 依赖关系

**外部依赖（游戏内，必须满足）：**

- 游戏语言为简体/繁体中文（OCR 匹配中文文案）；
- 背包 → 声骸页，用游戏内筛选器选出待升级声骸，按**等级升序**排序；
- 强化界面开启「阶段放入」；
- 关闭「同步调谐」；
- 热键：`b`（背包）、`esc`（返回）、`c`（上锁，可选）。

**框架依赖（ok-script）：**

- 截图捕获（WGC/BitBlt）、模板匹配、OCR（onnxocr）、PostMessage 后台输入；
- `BaseWWTask` 基类：`handle_monthly_card`、`click_skip_dialog_confirm`、`ensure_main`、`key_config`；
- 参考实现：`src/task/EnhanceEchoTask.py`（流程）、`src/task/MergeEchoTask.py`（骨架）。

**标定数据依赖（开发前置）：**

- `DETAIL_LEVEL_BOX`（详情页等级）、`PREVIEW_LEVEL_BOX`（强化预览等级）、`CONFIRM_BOX`（强化按钮）等坐标区域，需用 `main_debug.py` 实机标定。

## 6. 风险

- 官方用户协议禁止第三方工具，存在封号风险；建议仅个人学习、加随机延迟、控制批量、不长时间挂机。
- 游戏版本更新会改变 UI 布局与坐标，需依赖决策 4 快速重标定。
- OCR 误读可能导致误投料/误判等级，需多帧投票 + 复核闭环（见功能模块 02、04）。
