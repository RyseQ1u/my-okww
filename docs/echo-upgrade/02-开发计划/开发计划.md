## 阶段 0：文档与计划

- **目标**：建立结构化文档体系，明确目标、范围、决策、依赖、待办，作为后续开发的唯一依据。
- **交付物**：本目录（README、总体方案、开发计划、功能模块、测试计划、评审记录）。
- **验收**：总体方案 DoD 明确；每份功能文档五要素齐全。
- **状态**：进行中（本阶段）。

## 阶段 1：只读探针（标定 OCR）

- **目标**：在真实游戏环境里，能稳定打印"第一格声骸的当前等级"，**不点击任何按钮**。
- **关键活动**：
  1. 用 `main_debug.py` 启动，进入背包声骸页；
  2. 写临时脚本 dump 全屏 OCR 及归一化坐标；
  3. 从日志定位并标定 `DETAIL_LEVEL_BOX`、`PREVIEW_LEVEL_BOX`、`CONFIRM_BOX`、`ADD_MAT_BOX`、`FIRST_SLOT`、`SORT_BTN`；
  4. 验证 `read_level` 的 `max(nums)` 策略在真实 UI 下正确（不被材料数量/等级上限干扰）。
- **交付物**：标定后的坐标常量 + 标定截图存档 + 一份"坐标标定记录"。
- **验收标准**：连续 10 帧读取同一件声骸等级，结果一致且正确。
- **依赖**：阶段 0；用户提供真实游戏环境与截图。

## 阶段 2：单件打通（0 → 5）

- **目标**：单件声骸从 0 级强化到 5 级的完整闭环跑通。
- **关键活动**：
  1. 实现并验证 `select_first_echo` → `in_echo_detail` → 培养 → `enhance_to` → `confirm_enhance` → 复核等级；
  2. 验证预览等级闭环（决策 2 的层级 A）；
  3. 验证 `handle_dialogs` 能清掉"不再提示/调谐成功/点击任意位置"弹窗。
- **交付物**：可运行的单件流程代码。
- **验收标准**：0 → 5 升级成功，复核等级 == 5，无残留弹窗。
- **依赖**：阶段 1。

## 阶段 3：队列与终止判定

- **目标**：多件声骸依次处理，终止条件（首格等级 ≥ x）正确触发。
- **关键活动**：
  1. 完善 `run()` 主循环与 `process_one()` 的返回码（done/skip/fail/no_material）处理；
  2. 实现并验证 `back_to_list` + `back_to_list_top` 对 3.7"回列表自动选中刚强化声骸"的防御；
  3. 验证断点续跑（中断后重启能继续）。
- **交付物**：完整主循环代码。
- **验收标准**：
  - 混合队列（0/0/5/10/20，x=15）正确处理前 3 件、跳过 2 件；
  - 目标低于当前（全部 +20，x=5）立即结束、0 次操作；
  - 连续 50 件无死循环、无重复处理。
- **依赖**：阶段 2。

## 阶段 4：异常矩阵

- **目标**：穷举并处理文档《异常处理矩阵》的全部场景。
- **关键活动**：
  1. 逐条实现材料不足、贝币不足、OCR 失败、强化未变、弹窗、超时、UI 改版等处理；
  2. 补充"同一件连续异常"计数器与"单件超时"逻辑；
  3. 验证"只有环境不可用才终止，资源不足/单件失败一律降级"的原则。
- **交付物**：完整异常处理代码 + 对应测试。
- **验收标准**：异常矩阵 11 条场景全部通过测试（见 `04-测试计划`）。
- **依赖**：阶段 3。

## 阶段 5：增强（可选）

- **目标**：按需增强，非必需。
- **候选**：
  - 经验表（`echo_exp.json`，决策 2 层级 B）；
  - 精确退料到任意等级（当前 Out of scope）；
  - i18n 任务名/描述翻译。
- **验收**：按需单列。
- **依赖**：阶段 4。
