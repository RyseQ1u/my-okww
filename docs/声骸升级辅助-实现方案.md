# 声骸升级辅助（UpgradeEchoTask）实现方案

> 目标功能：用户事先在游戏内筛选好待升级的声骸，程序自动逐件定位并把每件强化到运行期指定的等级 x，材料不足等异常可预期地降级处理。

---

## 一、参考项目结构与实现方式

### 1.1 技术栈分层

ok-wuthering-waves（OK-WW）不是一个自研框架，它建立在 PyPI 包 `ok-script` 之上。理解这一点，后面所有代码都能对号入座：

```
┌─────────────────────────────────────────────┐
│  main.py → OK(config).start()               │  入口：装配执行器
├─────────────────────────────────────────────┤
│  ok-script（框架层，pip 依赖）                │  OK / Executor / BaseTask / BaseScene
│  · 截图(捕获) · 模板匹配 · OCR · YOLO · 输入  │  · 任务调度 · 配置UI · 通知 · 日志
├─────────────────────────────────────────────┤
│  ok-ww（业务层，本仓库）                      │
│  config.py · src/task/* · src/scene/*        │  · 具体游戏流程
│  src/char/* · src/combat/* · assets/templates│
└─────────────────────────────────────────────┘
```

**核心运行模型**：执行器持续循环"取一帧截图 → 模板匹配/OCR 识别 → 按识别结果点击 → 短睡眠 → 取下一帧"。任务类里写的不是"脚本步骤"，而是"在什么视觉状态下做什么"。

### 1.4 EnhanceEchoTask 逐段拆解（你的功能就是它的变体）

它的实际流程与硬编码坐标：

1. **前置**：用户在背包 → 声骸页，用游戏内筛选器选好目标，按等级**升序**排序。
2. `find_echo_enhance()` = `ocr(0.82, 0.86, 0.97, 0.96, match='培养')` —— 右下角"培养"按钮，**同时充当"是否停在声骸详情页"的探针**。
3. `select_0_level_echo()`：点列表**第一格** `(0.13, 0.21)`；用 `is_0_level()`（OCR 区域 `0.65,0.35→1,0.57` 是否存在"声骸技能"，0 级时才有）判断是否 0 级；若不是，点排序按钮 `(0.35, 0.917)` 两次把列表滚回顶部。
4. 点"培养" → 进强化页 → 循环点「阶段放入」（OCR 区域 `0.09,0.6→0.38,0.86`）直到按钮消失 → 点「强化并调谐」（`0.10,0.88→0.29,0.96`）。
5. 清弹窗：`不再提示` / `调谐成功` / `点击任意位置返回`。
6. 读词条：`ocr(0.09, 0.3, 0.40, 0.53)`，用 `property_pattern` 抓中文属性、`number_pattern` 抓数值，按 y 坐标就近配对 → `check_echo_stats()` 判定。
7. 不合格 → `弃置(z)`；5 词条 → `上锁(c)`；`esc` 回背包。
8. **终止条件**：第一格不再是 0 级 → 全处理完，输出统计并可选打开截图目录。

两个必须知道的细节：

- **3.7 版本起，从培养界面 esc 回背包后，游戏会自动选中并滚动到刚强化的那件声骸**，不再停在第一格。代码里那行注释就是为此打的补丁 —— 这意味着"回列表后第一格"的假设会变，你的实现要做防御（见 §3.4）。
- 它依赖**游戏内两个设置必须打开**：「阶段放入」和「同步调谐」，否则直接抛异常。你的功能不需要同步调谐（那是刷副词条用的），应当**关掉**，省调谐器也少一条失败路径。

## 二、需求拆解与三个关键设计决策

### 决策 1：不"识别声骸列表"，而是把列表当成队列

用户说"自动定位这些声骸"。有两条路：

**路线 A（推荐）：借力游戏内筛选器 + 等级升序排序，永远只处理第一格。**

- 用户已预筛 → 列表里只剩目标声骸；
- 按等级升序 → 第一格必然是最低级的待升级件；
- 升完一件，它等级变高，自动排到队尾 → 第一格自然变成下一件；
- **终止条件变成纯数值判断**：第一格等级 ≥ x 即全部完成。

好处：不需要识别"这是哪个声骸"、不涉及列表滚动、不受格子虚拟化和分辨率影响、天然支持断点续跑（下次开任务，已升级的件仍在队尾）。

**路线 B（昂贵）：图像识别 + 网格点击。**

需要标定首格与行列间距、逐格 OCR 等级角标、处理滚动（`scroll_relative`）与列表虚拟化，且游戏改版即失效。仅在你需要"跳着选特定声骸"时才值得做。

> 结论：以 A 为主体，B 只在"跳件"场景下作为可选能力。这也是原项目 `EnhanceEchoTask` 的选择，是经过实战验证的。

### 决策 2：目标等级用"预览等级闭环"，而不是经验表计算

强化面板里点「阶段放入」后，界面会显示投入材料后的**结果等级预览**。它是唯一可信的真值来源，优于任何经验公式。

三级降级策略：

| 层级 | 机制 | 精度 | 成本 |
|---|---|---|---|
| A 预览闭环 | 点一次阶段放入 → OCR 预览等级 → 到 x 停 | 高 | 需标定预览区域 |
| B 经验模型 | `data/echo_exp.json`：材料经验值 + 等级经验表，算好投放组合 | 中（游戏改数值即失准） | 需实测一次经验表 |
| C 档位模式 | 只支持 5/10/15/20/25（阶段档位），数阶段次数 | 高但粗 | 零标定 |

默认走 A，A 的预览区域读不到时自动退回 C。B 作为可选增强。

**关于溢出**：材料经验粒度是固定的，想停在 x 级可能做不到。默认策略是「允许溢出到最近可达等级并告警」，把"清空材料再逐个小材料加"的精确退料做成可选开关 —— 因为退料要操作减号/清空按钮，每多一个未标定的控件就多一个故障点。

### 决策 3：材料不足是"正常结束"，不是异常

这是体验上最容易做错的地方。材料耗尽时**抛异常会让整个任务红屏失败**，而正确的处理是：

- 记录本次完成 N 件、剩余 M 件；
- `log_info(..., notify=True)` 通知；
- 正常 `return`，任务优雅结束。

因为筛选条件和排序都还在，用户补充材料后**再点一次开始就能续跑**，无需任何状态文件。

## 三、实现方案

### 3.1 文件与注册

```
新增  src/task/UpgradeEchoTask.py        # 主任务
新增  assets/templates/echo_*.png         # 需标定的按钮模板（可选，优先用 OCR）
可选  data/echo_exp.json                  # 经验表（仅精确模式需要）
修改  config.py                           # 注册任务
修改  i18n/                               # 任务名/描述翻译（可选）
```

`config.py` 的 `'onetime_tasks'` 列表里追加（放在 EnhanceEchoTask 之后，GUI 顺序即列表顺序）：

```python
'onetime_tasks': [
    ...
    ["src.task.EnhanceEchoTask", "EnhanceEchoTask"],
    ["src.task.UpgradeEchoTask", "UpgradeEchoTask"],   # ← 新增
    ...
],
```

### 3.2 主循环（状态机）

```
校验前置(在声骸列表页?) ─否→ 明确报错+退出
        │是
        ▼
   点第一格 → 读当前等级 L
        │
   L ≥ x ─是→ 全部完成，统计+通知+退出
        │否
        ▼
   点「培养」→ 进强化页 → 读 L 复核
        │
        ▼
   ┌─ 点一次「阶段放入」→ 读预览等级 P
   │      P ≥ x  → 停止投料
   │      P < x  → 继续（最多 8 轮）
   │      按钮消失 → 材料耗尽 → 结束分支
   └─
        ▼
   点「强化」→ 校验等级 ≥ x
        │
        否 → 重试 1 次 → 仍失败则记失败、跳过
        ▼
   回列表（esc）→ 处理下一件
```

### 3.3 关键实现要点

**a) 定位与等级读取**

```python
def read_level(self, box):
    texts = self.ocr(box=self.box_of_screen(*box))      # 归一化 → 像素
    nums = [int(m.group(1)) for t in texts
            if (m := re.search(r"(\d{1,2})", t.name))]
    return max(nums) if nums else None                  # 取最大值，避开 1/25 之类的分母
```

- 读失败要**多帧投票**（连续 3 帧取众数），单帧 OCR 抖动很常见；
- 区域必须用 `main_debug.py` 实机标定（见 §5）。

**b) 投料循环**

```python
def enhance_to(self, target):
    for _ in range(8):
        if not (btn := self.find_add_mat()):            # 「阶段放入」消失
            return "no_material"
        self.click(btn, after_sleep=0.4)
        preview = self.read_preview_level()
        if preview is None:
            self.batches += 1                           # 退回档位模式：数次数
            continue
        if preview >= target:
            return "reached"
    return "max_batches"
```

**c) 结束判定（核心）**

```python
level = self.read_level(DETAIL_LEVEL_BOX)
if level is not None and level >= target:
    self.log_info(f"首格等级 {level} ≥ {target}，全部完成", notify=True)
    return
```

这一行替换掉 `EnhanceEchoTask` 里的 `select_0_level_echo()`，是整个改造的关键 —— 从"找 0 级"变成"找未达标"。

**d) 防御 3.7 的"自动选中刚强化声骸"**

回列表后不要盲目相信停在第几格。做法：回列表后**先点排序按钮两次回顶**，再点第一格，再读等级复核。若复核等级 ≠ 预期（说明选错了格），再点一次排序回顶重试。

### 3.4 配置项（GUI 自动生成）

| 配置键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `目标等级` | drop_down `[1..25]` | 15 | 运行时指定 x；用 drop_down 覆盖任意整数，无需自造控件类型 |
| `允许溢出` | bool | True | 材料粒度粗导致超 x 时是否接受 |
| `达到目标后上锁` | bool | False | 复用 `c` 键上锁，便于事后复核 |
| `材料耗尽时暂停` | bool | True | 结束后 `pause()` 而非直接退出，方便看现场 |
| `单件超时(秒)` | int | 90 | 防卡死 |
| `最大处理数量` | int | 200 | 防误触跑一整晚 |

### 3.5 与 EnhanceEchoTask 的差异清单（改造工作量）

| 项 | EnhanceEchoTask | 本任务 |
|---|---|---|
| 终止条件 | 首格非 0 级 | 首格等级 ≥ x |
| 目标 | 固定升到满级 | 运行期指定 x |
| 词条判定 | 有（双爆/有效词条打分） | **全部删除** |
| 调谐 | 同步调谐，必须开 | **不开**，避免调谐器与弹窗 |
| 弃置/上锁 | 判定后二选一 | 不弃置，可选上锁 |
| 截图 | 每件存图 | 仅失败件存图 |
| 异常 | 多为 `raise` | 分类降级，尽量继续 |

## 四、异常处理矩阵

| # | 场景 | 检测方式 | 处理策略 |
|---|---|---|---|
| 1 | 不在声骸列表页 | `ocr('培养')` 连续失败 3 帧 | 提示"请先在背包声骸页筛选+升序排序"，`notify=True` 后退出 |
| 2 | 等级 OCR 读不到 | 3 帧内无可解析数字 | 退回档位模式（数阶段次数）；仍失败则跳过该件并记日志 |
| 3 | **材料不足** | 「阶段放入」消失 且 等级 < x | 结束本次，统计"完成 N / 待处理 M"，通知 |
| 4 | 贝币不足 | 弹窗 OCR 命中"贝币"/"不足" | 同 3，且不点确认（避免误消耗） |
| 5 | 已达该稀有度等级上限 | 投料后等级不变、按钮灰 | 标记"已达上限"跳过 |
| 6 | 强化后等级未变 | 复核等级 == 投料前 | 重试 1 次；再失败则记失败并跳过 |
| 7 | 月卡/公告/断线弹窗 | `handle_monthly_card()` / `click_skip_dialog_confirm()` | 复用基类，环回主循环 |
| 8 | 同一件连续异常 3 次 | 计数器 | 中止任务，保留现场 `pause()`，防死循环 |
| 9 | 单件超时 | `time.time() - t0 > 90` | 放弃该件，`esc` 回列表继续 |
| 10 | 模板/UI 改版 | 关键模板缺失 | 明确报"疑似版本更新，请重新标定 §5 区域"，不要静默失败 |
| 11 | 误点进角色/武器页 | 详情页探针不匹配 | `esc` 一次后重新校验，最多 2 次 |

设计原则：**只有"环境不可用"才抛异常终止；"资源不足/单件失败"一律降级继续或优雅结束。**

## 五、标定与测试（坐标是这套方案唯一的硬成本）

### 5.1 标定步骤

1. 用 `python main_debug.py` 启动（会绘制识别框）；
2. 进背包声骸页，手动做一次"培养 → 阶段放入 → 强化"，全程截图；
3. 写个临时脚本 dump 全屏 OCR 及其归一化坐标：

```python
for t in self.ocr(0, 0, 1, 1):
    self.log_info(f"{t.name!r}  x={t.x/self.width:.3f} y={t.y/self.height:.3f} "
                  f"w={t.width/self.width:.3f} h={t.height/self.height:.3f}")
```

4. 从日志里定位三个区域：**详情页等级**、**强化面板预览等级**、**「强化」按钮**；
5. 把结果写进类常量（`DETAIL_LEVEL_BOX` 等），全部用归一化值，跨分辨率生效。

### 5.2 测试用例

| 用例 | 输入 | 期望 |
|---|---|---|
| 单件冒烟 | 1 个 +0 声骸，x=5 | 停 +5，等级复核通过 |
| 混合队列 | 5 件初始 0/0/5/10/20，x=15 | 前 3 件处理，后 2 件因 ≥15 跳过 |
| 目标低于当前 | 全部 +20，x=5 | 立即结束，0 次操作 |
| 溢出路径 | x=7（非 5 的倍数），`允许溢出=True` | 停在可达等级并告警 |
| 材料耗尽 | 清空经验材料 | 优雅结束 + 通知，不红屏 |
| 贝币耗尽 | 保留材料清空贝币 | 同上 |
| 界面漂移 | 强化前插入月卡弹窗 | 自动关闭后继续 |
| 长稳 | 连续 50 件，x=25 | 无内存增长，成功率 >95% |

### 5.3 实施顺序（建议）

1. 只读探针：能稳定打印"第一格等级"，不点任何按钮 —— 先把 OCR 标定坐实；
2. 打通单件：0 → 5；
3. 加队列与终止条件；
4. 加异常矩阵；
5. 再考虑精确模式与经验表。

## 六、风险提示

- 官方用户协议禁止第三方工具，**存在封号风险**；仓库 README 与 config.py 的 about 段均已明示。
- 建议仅作个人学习用途，加随机延迟、控制单次批量，不做长时间挂机。
- 游戏版本更新会改变 UI 布局与坐标，方案已把坐标集中为类常量以便快速重标定。
